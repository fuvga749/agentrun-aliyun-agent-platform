## AgentRun 到底是什么？先确认你找的是哪一个

阿里云的 AgentRun 是一个覆盖智能体应用开发、部署、运维全生命周期的平台，本质上把四样东西打包在了一起：智能体应用的云原生运行时、沙箱平台、模型治理与工具生态，外加内置的安全和可观测能力。团队要做的只剩下业务逻辑和智能体行为本身，服务器、容器、Kubernetes 这些都不用自己管。

有必要先排个雷：叫"AgentRun"的产品不止这一个。GitHub 上至少有两个同名开源项目——一个用 Go 写，给 AI Agent 会话做统一的 Engine/Process 接口抽象；另一个是 Python 库，负责让大模型生成的代码在 Docker 容器里安全执行，还有一个基于前者的 OpenAI 兼容网关。海外一家叫 Grep.ai 的公司也用 AgentRun 这个名字，做的是面向反洗钱等合规场景的智能体 harness。这些和阿里云的平台互不相干。如果你要找的就是阿里云这个，往下看。

## 底层三件套：运行时、沙箱、模型网关各管一段

官方把 AgentRun 拆成运行时、沙箱、模型治理三大块，日常使用中感知最强的也是这三块。分开讲：

### Serverless 运行时：会话亲和加缩容到零

运行时由 Function Compute 支撑，靠弹性伸缩应对稀疏调用和流量突增。两个设计对智能体场景特别重要：一是会话亲和，同一会话的请求会被路由到同一个实例，多轮对话和状态管理不用自己写粘性逻辑；二是支持缩容到零，会话不活跃后资源自动释放。

冷启动问题官方也给了方案：短暂闲置的实例进入轻度休眠，新请求来了毫秒级唤醒；长时间没流量的实例进入更省电的深度休眠，恢复也在秒级。休眠期间计费会相应调整，在性能和成本之间做平衡。

### 沙箱：代码解释器和浏览器自动化都内置

沙箱运行时内置 50 多种语言支持，也允许带自定义镜像。开箱即用的能力有两类：

- **Code Interpreter**：安全执行 Python、Node.js、Java 代码，带文件和会话管理；
- **Browser Use**：通过 CDP over WebSocket 提供稳定的浏览器自动化环境，兼容 Puppeteer 和 Playwright。

Computer Use 和 Mobile Use 在官方规划里，还没上线，这点别被一些文章提前“安排上”。安全隔离用的是 MicroVM 安全容器，做到请求、实例、会话三级隔离；存储可以挂 OSS 或 NAS，且相互隔离。

### 模型网关：Qwen、DeepSeek 都能接，治理能力在代理层

模型统一走一个代理层，支持 Qwen、DeepSeek 等主流模型和开源模型；FunModel 能把开源模型一键托管成 OpenAI 兼容 API；还有向量模型管理，对应检索和 RAG 场景。治理能力包括多模型负载均衡、故障 fallback、并发和超时控制、内容审核、按 token 限流、自动重试和成本监控。

对已经在自己服务里调模型 API 的团队，有个省事的地方：统一 HTTP API 兼容 OpenAI Chat Completions 协议，多语言 SDK 封装好了鉴权和调用细节，已有的 OpenAI 调用代码迁移成本主要在换地址和鉴权。

## 什么时候该用 AgentRun，什么时候不必

已经养着成熟工程团队、自己维护着一整套基础设施的团队，未必需要整体迁移。AgentRun 比较务实的一点是支持模块化接入：只用沙箱、只用模型代理、只用可观测能力，都可以单独拿去和现有系统集成，官方明确说这种方式不需要把整栈搬进一个封闭平台。

这些情况下值得考虑：

- 团队在用 LangChain、AgentScope、CrewAI 或 Google ADK，但不想再自己运维运行时和沙箱；
- 业务岗想自己搭简单智能体，不想排研发的期；
- 需要代码执行、浏览器自动化这类沙箱能力，又不想自己管容器和安全隔离。

这些情况建议先缓一缓：

- 对运行环境有完全自控、私有化部署硬性要求的团队，先和官方确认边界再动手；
- 只想跑一次性小任务，直接调模型 API 更省事，引入平台属于杀鸡用牛刀。
